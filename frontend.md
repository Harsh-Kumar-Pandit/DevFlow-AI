# DevFlow AI — Frontend Design & Implementation Bible

> Designed to feel like Linear × Vercel × Notion. Not Jira.

---

## 1. Design System

### Philosophy
Every pixel is intentional. Every interaction has weight. The product should feel like it was built by a team that cares deeply about craft — not generated by a template.

### Core Principles
- **Elevation over borders** — Use shadows and depth, not outlines
- **Space is luxury** — Whitespace communicates confidence
- **Motion has meaning** — Every animation communicates state
- **Typography is hierarchy** — Size, weight, tracking tell the story
- **Dark-first, not dark-mode** — The dark theme IS the design

## 9. Animation Plan

### Page Transitions
```
Enter: opacity 0→1, y +16→0, duration 0.3s, ease: easeOut
Exit:  opacity 1→0, y 0→-8, duration 0.2s, ease: easeIn
```

### Sidebar
```
Expand: width 64→240px, duration 0.25s, spring(stiffness:300, damping:30)
Icons:  x-shift with stagger 0.03s per item
Labels: fade in with 0.1s delay after width settled
```

### Kanban Cards
```
Drag start: scale 1.02, rotate ±2deg, shadow-2xl
Drop zone:  background pulse, border brightness
Drop:       spring bounce on card settle
```

### Drawers
```
Slide from right: x 100%→0, duration 0.35s, ease: easeOut
Backdrop:         opacity 0→0.5, same duration
Close:            x 0→100%, duration 0.25s
```

### AI Copilot Button
```
Idle:     subtle pulse glow (3s loop)
Active:   expand to full panel (spring)
Thinking: rotating gradient border
```

### Loading States
```
Skeleton: shimmer animation, from-surface via-surface2 to-surface
Cards:    staggered fade in with 0.05s delay
Data:     number counters animate up from 0
```

### Micro-interactions
```
Button click:    scale 0.97 for 100ms
Input focus:     border color + ring glow
Badge hover:     slight scale 1.05
Avatar hover:    ring + tooltip appear
Notification:    slide in from right + bounce
```

## 12. Integration Notes — Backend APIs & Socket.IO

### Axios Configuration
```javascript
// All requests include credentials for HTTP-only cookie auth
axios.defaults.withCredentials = true;
axios.defaults.baseURL = "http://localhost:5000/api";
```

### Authentication Flow
1. `POST /auth/register` or `POST /auth/login` → sets `token` cookie
2. On app load: `GET /auth/me` — if 401, redirect to `/login`
3. All subsequent requests auto-include the cookie

### Socket.IO Connection
```javascript
const socket = io("http://localhost:5000", {
  withCredentials: true  // sends token cookie
});
```

### Events to Listen On (from server)
| Event | When | Action |
|-------|------|--------|
| `online-users` | Any connection/disconnect | Update presence indicators |
| `notification` | Task assigned, join accepted | Toast + badge increment |
| `task-status-updated` | Status change via API | Re-render Kanban column |
| `comment-added` | New comment on open task | Append to comment list |
| `comment-updated` | Comment edit | Replace comment in list |
| `comment-deleted` | Comment deletion | Remove from list |

### Events to Emit (from client)
| Event | When |
|-------|------|
| `join-workspace` | Enter workspace view |
| `leave-workspace` | Leave workspace view |
| `join-task` | Open task drawer |
| `leave-task` | Close task drawer |

### File Upload Flow
1. `POST /upload` with `multipart/form-data` → returns `{ url, publicId, originalName }`
2. `POST /task/:taskId/attachment` with `{ url, publicId, fileName }` — attaches to task
3. `DELETE /upload/:publicId` → removes from Cloudinary
4. `DELETE /task/:taskId/attachment/:publicId` → removes from task

### AI Endpoints (fire-and-forget, streaming not supported)
All return plain text or JSON. Show loading state while waiting.
- Generate description: `POST /ai/generate-task-description`
- Suggest priority: `POST /ai/suggest-priority`
- Break into subtasks: `POST /ai/break-task`
- Project summary: `POST /ai/project-summary`
- Sprint summary: `POST /ai/sprint-summary`
- Chat: `POST /ai/chat`

## 13. State Management

### Context Structure
```
AuthContext    → user, login, logout, loading
SocketContext  → socket instance, online users
WorkspaceContext → current workspace, workspaces list, projects
NotificationContext → notifications[], unreadCount, actions
```

### Server State
Use local component state + custom hooks calling services.
No external state library needed (no Redux/Zustand).
All data fetching inside hooks, re-fetched on dependency changes.

## 14. Global Search (Ctrl+K)

Searches across:
- Projects (by name)
- Tasks (by title, status, priority)
- Members (by name, username)
- Comments (by message content)

UI: Full-screen modal overlay with:
- Grouped results with section headers
- Keyboard navigation (↑↓ to move, Enter to select, Esc to close)
- Recent searches persisted to localStorage
- Command palette for quick actions

## 16. Performance Strategy

- Lazy-load all page-level components via `React.lazy + Suspense`
- Debounce search input by 300ms
- Virtualize long lists (comments, activity feed) if > 50 items
- Image optimization: Cloudinary auto-format + resize params in URL
- Kanban: only re-render changed columns on socket update
- Memoize expensive component trees with `React.memo` + `useMemo`
